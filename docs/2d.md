# 2D 渲染器设计

## 绘制顺序

`Layered2DRenderer` 持有文字和图片的渲染单元。每帧收集单元，按 `modelMatrix[3].z` 从小到大排序，后绘制的单元覆盖在前面的单元之上；相同 Z 值的顺序不保证。Canvas 为 UI 节点分配遍历顺序作为 Z 值。

2D pass 只绑定颜色附件，启用颜色混合，关闭深度测试、深度写入和背面剔除，支持负缩放形成的镜像。每个渲染单元独立产生一次实例绘制；材质状态仅在有序列表中相邻单元的材质变化时切换。

## Quad 与渲染单元

`QuadInstanceGPU` 共 64 字节：

| 字段 | 含义 |
| --- | --- |
| `quadRect` | 局部矩形 `(minX, minY, maxX, maxY)`，UI 使用左上原点 |
| `uvRect` | 采样矩形；文字使用字体图集像素坐标，图片使用归一化 UV |
| `color` | 每个 Quad 的 RGBA 颜色 |
| `atlasInfo` | `.x` 为文字的图集类型（0 静态、1 动态）或图片的 bindless 纹理索引，其他分量保留 |

`QuadManager` 持有一份 CPU 数据和 `MAX_FRAMES_IN_FLIGHT` 份 GPU storage buffer。每份缓冲固定容纳 8192 个 Quad，按 512 个 Quad 分为 16 个更新块。修改块时将其更新计数设为帧副本数，随后每帧同步当前 GPU buffer 中对应的块并递减计数。空闲槽位通过列表分配和回收，Quad ID 就是全局槽位索引。

`QuadManager::Get(QuadID)` 返回 CPU Quad 的只读引用，调用方必须持有尚未释放的有效 ID，引用只在槽位释放或 Reset 前有效。修改通过 `Update` 或 `UpdateColor` 完成，以同步逐帧更新标记。UI 的属性读取和保存使用这份 CPU 数据。

`Layered2DRenderUnit` 保存模型矩阵和 Quad ID 列表。Quad ID 作为实例顶点属性，shader 根据 ID 读取 Quad，并为每个实例生成六个顶点。单元使用共享顶点缓冲池保存逐帧 Quad ID 数据。push constants 包含模型矩阵、viewport 尺寸和字体图集尺寸，图片 shader 直接使用归一化 UV。

## 描述符与材质

文字使用 Renderer 持有的逐帧 set 0：

- binding 0：静态字体图集。
- binding 1：当前帧的动态字体图集。
- binding 2：当前帧的 Quad storage buffer。

图片使用另一组逐帧 set 0，由内置图片 shader 定义：

- binding 0：当前帧的 Quad storage buffer。
- binding 1：`sampler2D textures[]`，容量为 `DEFAULT_BINDLESS_CNT`（1024）。

两种 shader 使用各自匹配的描述符布局。图片 shader 通过 `nonuniformEXT(textureIndex)` 采样，输出采样值乘 Quad 颜色。所有普通 UIImage 共用 `GetImageMaterial()` 返回的内置材质和对应 pipeline，纹理差异由 Quad 索引表达。

`Layered2DRenderer` 通过 `Material*` 索引并持有 `Layered2DMaterialState`：

- `material`：共享所有权，保证缓存期间有效。
- `pipeline`：该材质在 2D pass 中的图形管线。
- `commonDescriptorSet`：可选的材质纹理 set 1。

图片纹理表由 Renderer 管理，图片默认材质不包含逐图片纹理绑定。分配单元时查找或创建材质状态；材质状态保留到 Reset 或析构。

## 图片纹理表与逐帧更新

`RegisterImageTexture` 使用纹理对象指针的哈希表查找已有索引，平均 O(1)。同一纹理对象共享索引，每次注册增加使用计数。新纹理优先复用空闲列表中的槽位，没有空闲槽位时追加到表中；表持有 `shared_ptr<Texture2D>`。空纹理返回永久保留的白色槽位 0，其余 1023 个槽位用于图片。容量耗尽时返回错误。

每次成功注册须配对调用 `UnregisterImageTexture(index)`，传入仍持有注册的有效索引；对白色槽位 0 注销无操作。最后一个使用者注销时，删除指针索引映射，释放 CPU 表的纹理引用，并立即将槽位放回空闲列表。已有图片的索引保持稳定。UIImage 换图先注册新纹理，成功后注销旧纹理；节点卸载时注销当前纹理，构造中 Quad 分配失败也会归还注册。

每个 in-flight frame 有独立的图片描述符集、纹理引用快照和脏标记。CPU 表的槽位内容变化时将所有帧标脏。绘制前的 `syncImageTextures(currentFrame)` 在当前帧完成同步等待后，将 CPU 表写入该帧的描述符集，空闲槽位绑定白色纹理，再替换该帧的引用快照并清除脏标记。同步扫描表的已分配范围，上限为 1024；未标脏的帧不写描述符。

CPU 槽位可以立即复用，其他在飞行帧的描述符和引用快照仍保留旧纹理，直至各自完成并同步。Quad buffer 同样按当前帧同步，保证该帧的纹理索引与描述符对应。Renderer Reset 先等待 GPU 完成，再清理单元、材质状态、图片表和各帧快照，保留白色纹理并将所有帧标脏。析构释放逐帧描述符集。Reset 会使此前返回的图片索引失效，调用方须与所属 UI 节点一起重建注册。

## 字体图集

静态图集由 `Font` 持有，动态图集的 CPU 像素也由 `Font` 保存。Renderer 持有逐帧动态纹理及 staging buffer。动态字形发生变化后，按字体的更新计数逐帧上传整张动态图集。两种字体图集采用 `R8_UNORM` SDF，文字 shader 将距离值转换为覆盖率，再乘文字 Alpha。

## 渲染单元操作

- `AllocateUnit`：接受材质、模型矩阵和 Quad ID 列表，返回单元 ID；Quad 槽位由调用方管理。
- `DestroyUnit`：销毁单元并归还其 Quad ID 顶点缓冲分配；不存在的 ID 无操作。
- `UpdateUnitQuadIDs`：更新实例 ID 列表并标记逐帧顶点缓冲待同步；ID 不存在时返回 false。
- `GetUnit`：按 ID 查找单元，调用方可以更新模型矩阵。

单元保存在 `std::map` 中，每帧排序复杂度为 O(n log n)。Reset 清理单元后清理材质状态，重置顶点缓冲池、单元 ID 分配器和图片纹理表。
